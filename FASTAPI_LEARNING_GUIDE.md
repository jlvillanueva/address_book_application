# Learning the Address Book API

This guide is meant to help you understand the project, not just run it. The
examples refer to the files in this repository. Read a section, open that file,
and trace how one request moves through the code.

## Start with the request flow

For a request to create an address, the flow is:

```text
POST /addresses
    -> app/route/addresses.py
    -> app/services/addresses.py
    -> app/models/addresses.py and app/database.py
    -> app/schemas.py shapes the response
```

This is similar to the resource/route, operation module, and model split in the
Flask APIs you know. The main differences are that FastAPI reads type
annotations to validate and document requests, and `Depends` supplies shared
things such as database sessions.

## What to learn, file by file

### 1. `app/services/distance.py` — plain Python first

Start here because it does not depend on FastAPI or the database.

`distance_in_kilometers` takes two coordinate pairs:

- `latitude_a` and `longitude_a` describe the starting point.
- `latitude_b` and `longitude_b` describe the other point.
- The function returns the approximate great-circle distance in kilometers.

The function converts degrees to radians because Python's trigonometry
functions expect radians. It then applies the Haversine formula and scales the
result by the Earth's mean radius. In the nearby-search flow, point A is the
location from the request and point B is one saved address.

The `float` annotations describe expected types. They do not check latitude
and longitude ranges; those checks happen at the API boundary.

**Try:** Call the function with the same point twice and check that the result
is zero. Then try two different points and confirm the result is positive.

### 2. `app/schemas.py` — request validation and response shapes

These are Pydantic models, not database tables.

- `AddressInput` describes fields accepted when creating or replacing an
  address. `Field` sets length and coordinate limits.
- `AddressResponse` describes what the API returns, including the generated
  ID and timestamps.
- `NearbyAddressResponse` extends the address response with `distance_km`.

This is one of FastAPI's biggest differences from a typical Flask route that
manually reads `request.json` and checks every field. FastAPI uses the function
parameter type to parse and validate the incoming JSON, returning `422` if it
does not match.

`ConfigDict(from_attributes=True)` lets Pydantic build a response from a
SQLAlchemy object's attributes.

**Try:** Change a test payload's latitude to `91`. The request should be
rejected before the route function runs.

### 3. `app/models/addresses.py` — the database table

`AddressModel` is the SQLAlchemy model for the `addresses` table.
`__tablename__` sets the table name. Each `mapped_column` defines one table
column, including its Python type and database constraints.

`Base` comes from `app/database.py`; inheriting from it registers this model
with SQLAlchemy metadata. The timestamp defaults use UTC. `updated_at` also
has an `onupdate` function so SQLAlchemy refreshes it when the row is changed.

Keep the distinction clear:

- Pydantic schema: what the API accepts or returns.
- SQLAlchemy model: how the row is stored in the database.

**Try:** Find the primary key and identify which columns the client must send
and which values are generated by the application.

### 4. `app/database.py` — engine, sessions, and `Depends`

- `create_engine` configures the SQLite connection.
- `SessionLocal` is a factory that creates database sessions.
- `Base` is the parent class for database models.
- `get_db` creates a session, yields it to its caller, and closes it afterward.

In a route, `db: Session = Depends(get_db)` asks FastAPI to call `get_db` and
provide the yielded session. This is dependency injection: the route declares
what it needs, and FastAPI supplies it. The `finally` block runs when the
request is finished, including when an error occurs.

The SQLite `check_same_thread` option is needed for this application's
request-handling setup.

**Try:** Trace `get_db` from its definition to one route's `Depends(get_db)`
parameter. Notice that the route does not manually open or close the session.

### 5. `app/services/addresses.py` — address operations

This module keeps database work out of the HTTP handlers. Its functions add,
list, get, update, delete, or search for addresses.

For example, `AddressAdd` converts the validated input schema to a dictionary,
creates a model, adds it to the session, commits the transaction, and refreshes
the object so database-generated values are available.

`AddressListNearby` loads saved addresses, calculates each distance, keeps the
ones inside the requested radius, and sorts them nearest first.

The operation names use the capitalized style seen in your Flask modules. That
is valid Python, though lowercase `snake_case` is the usual Python convention.
For this exercise, focus on understanding the function's job and inputs/outputs.

**Try:** Follow the return value of `AddressGet` when an ID exists and when it
does not. The route decides what HTTP response to send based on that result.

### 6. `app/route/addresses.py` — FastAPI endpoints

`APIRouter` groups endpoints under `/addresses`. Each decorator describes an
HTTP method and path. FastAPI inspects the function signature to identify path
parameters, query parameters, request bodies, response models, and
dependencies.

Examples:

- `address: AddressInput` is parsed from the JSON request body.
- `address_id: int` comes from the URL path for `/{address_id}`.
- `Query(...)` defines and validates query parameters.
- `Depends(get_db)` provides a database session.
- `response_model=AddressResponse` filters and documents the response shape.
- `HTTPException` returns an HTTP error such as `404`.

The `/nearby` route is registered before `/{address_id}` so the static
`/nearby` path is not mistaken for an address ID.

**Try:** Pick one endpoint and say which values come from the body, URL, query
string, and dependency. Then trace the service call and response.

### 7. `app/main.py` — build the application

This file creates the `FastAPI` application and registers the address router.
The `app` variable is what Uvicorn imports when you run
`uvicorn app.main:app --reload`.

There is an important detail to check in the current file: it defines a
`lifespan` function that would create the database tables, but the `FastAPI`
constructor currently does not pass `lifespan=lifespan`. A function definition
alone does not make FastAPI run it. Before relying on startup to create tables,
check with your mentor or add the lifespan argument and test that the app starts
with a fresh database.

**Try:** Find where `addresses_router` is included and where the `app` object
is created. Explain why Uvicorn needs the module path and variable name.

### 8. `tests/test_addresses.py` — prove behavior

The tests use FastAPI's `TestClient` to make HTTP requests without manually
starting a server. A fixture creates a temporary SQLite database and overrides
`get_db`, so test data stays separate from the normal application database.

The tests cover CRUD operations, pagination, nearby search, invalid
coordinates, and missing addresses. The assertions check observable behavior:
status codes and returned JSON.

**Try:** Add a test for a negative search radius or for an empty address name.
Predict the expected status code, run the test, and inspect any failure.

### 9. `requirements.txt` and `README.md`

`requirements.txt` lists installable project dependencies. The README explains
how to install, run, and test the API and gives example requests.

The empty `__init__.py` files mark directories as Python packages so imports
such as `from app.services import addresses` work consistently.

## Run and check your understanding

From the `address_book_api` directory:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
uvicorn app.main:app --reload
```

Open <http://127.0.0.1:8000/docs> to send requests through Swagger. In another
terminal, from the same project directory, run:

```bash
pytest
```

Before the assessment, practice explaining one request end-to-end. For
example: “A POST body is validated as `AddressInput`; the route receives a
database session through `Depends`; it calls the service; the service commits
an `AddressModel`; and FastAPI serializes the result using
`AddressResponse`.”
